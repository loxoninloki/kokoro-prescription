# 服薬報酬の日次上限と既存データ保護

作業先: feature/persistent-navigation。本番ブランチ・保存済みプロトタイプは未変更。

## 確定動作
服薬記録の件数に関係なく、新規報酬は1日最大10 EXP＋10マカロン。日付単位の `medication-day:YYYY-MM-DD` を1件だけ生成する。薬剤登録・非表示・服薬日時・チェック操作は維持する。同日チェック切替・追加薬剤・再起動では追加付与しない。新規日の全セルフケア基本最大値は70 EXP＋70マカロン。

## 移行
既存のreward ledgerに任意フィールド `medicationPolicy`（version、effectiveDate、legacyDayXp）を追加。保存キーとversion=1は維持する。

初回適用時、実在する旧服薬チェックと旧creditedXpを照合。未精算の実在する旧記録は従来IDで一度だけ精算し、日付別の旧EXPを固定する。既存のearned/spent、確定済み旧イベントを削除・減算しない。旧EXPの固定値は現在の記録件数と旧台帳の日次合計の大きい方を保護する。非表示にした薬や確定後にチェックを解除した履歴も台帳から保護できる。

以後は旧日付に薬剤やチェックを追加しても、固定した旧EXPを増やさない。移行済み台帳では旧個別イベントの新規加算を禁止する。旧イベントがある日の新形式イベントは、支払い済みマーカーとして記録するがearnedを増やさない。逆順（新形式を先に持つ台帳への旧形式イベント）も再付与しない。マーカーと旧イベントを合算してEXPを計算しない。

新規日の服薬EXPも確定済み日付イベントから保持するため、解除・再チェックでEXPや報酬を繰り返し取得できない。純粋な未獲得・記録0件の日は0 EXP。

基準日は固定の2026-11-07に遡及させない。初回適用時の日本時間の日付を保存し、任意のビルド変数 `REACT_APP_MEDICATION_REWARD_RELEASE_DAY` が指定されていれば実際の承認済みリリース日として保存する。本番公開時に指定する場合は実際の公開日を使用する。日付だけで過去記録を再計算せず、初回の実在記録スナップショットを保護する。移行済みのpolicyがある場合は再実行しない。

移行は既存ログイン保存の共通ロック・復旧ジャーナル内で確定する。途中失敗時は成功表示を出さず復旧後に再試行する。初回表示も保存前の旧EXPを読み取り専用で保護し、移行前後のレベル急落を避ける。

## バックアップ
既存のrewardsフィールドにpolicyと旧/新creditedXpが含まれるため、書き出し形式のバージョンは変更しない。復元時にpolicyを検証・保持する。台帳のない旧バックアップも実在する旧記録を取り込み、既存台帳・保護済み日次XPを保持して再復元の追加付与を防止する。復元の変更は既存ロールバック対象に含める。

## UI
服薬画面に以下を表示する。
「服薬を記録すると、1日最大10 EXP＋10マカロンを獲得できます。お薬の種類や回数によって報酬は増えません。」
当日の台帳に獲得履歴がある場合のみ「今日の服薬記録ボーナスは獲得済みです ✓」。2件目以降の追加報酬演出はない。
