# プレゼントボックス・一斉配布

ホームの表示切替ボタン直下の小さなギフトアイコンから開く。通常ログインのマカロンはボックス対象外。既存の自動付与は維持し、家具・コーデ等の既存特典は確認で履歴へ移す。運営の新規一斉特典は「受け取る」で付与し、受取履歴へ移す。

運営は public/presents.json の gifts に配布内容を登録し、統合ブランチへのPR・検証・Cloudflare配信を行う。管理者専用画面は設けず、既存GitHubのリポジトリ編集権限で管理する。公開ファイルに秘密情報や個人宛情報を書かない。初期配布一覧は空であり、検証用特典は本番の一覧に登録しない。

例（説明用。自動では配布されない）:

```json
{"version":1,"gifts":[{"id":"celebration-20261108","title":"運営からのお祝い","startsAt":"2026-11-08T00:00:00+09:00","endsAt":"2026-12-01T00:00:00+09:00","macarons":0,"tickets":1,"itemIds":["lavender-bloom"]}]}
```

idは英小文字・数字・ハイフン・アンダースコア、80文字以内。一度使用したidは再利用しない。日時はタイムゾーン付きISO形式。endsAtは任意。数量は0〜100000の整数。itemIdsは既存コーデ・家具のID。受取履歴を復旧できるよう、配布終了後も一覧から削除せずendsAtで終了させる。

受信は同一オリジンのpresents.jsonをno-storeで取得。受取直前にも配布内容と期間を再取得する。通貨と所持品・受取済みID・受取日時を、既存の報酬保存ロック内の1回のwallet書き込みで反映する。衣装や家具は所持品へ追加し、家具は既存Appの同期でルーム所有情報へ反映する。連打・複数タブの同じIDは1回だけ。通信失敗時・保存失敗時は受取済みにしない。

RewardStateに互換性のある任意フィールドpresentClaims / presentClaimDates / presentTicketCreditを追加。旧データは未指定のまま読み込める。presentTicketCreditは運営から付与されたチケットだけ累積し、既存のチケット検証に加算する。既存ログイン日数・報酬計算・育成条件を変更しない。独立した履歴キーへの書込失敗時はwallet内の受取情報から履歴を再構築する。履歴削除後もwalletの受取済みIDは消さず再受取を防止する。

制限: アカウントがないため受取制限は同じ端末の保存データ単位。端末データ削除や古いバックアップの復元による再受取をサーバーで防ぐことはできない。利用者単位の厳密な一回制限、個別配布、プッシュ通知は対象外。配布一覧を取得できるオンライン状態が受取に必要。履歴は端末内保存。

検証: TypeScript・27スイート126テスト・本番ビルド。幅375pxブラウザで表示切替と同じx座標、直下に52×51pxのボタンを確認。隔離した検証データで運営一覧受信→チケット1枚と花あかり受取→履歴移動を確認。公開一覧は空のまま。iPhone実機は確認待ち。
