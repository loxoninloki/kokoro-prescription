## 服薬の修正判断

修正候補の既存38テストは成功した。一方、追加回帰では旧服薬の解除によるEXP減少、日次報酬の後の旧イベント再投入、同一バッチの旧新イベント混在による二重払いを再現した。候補の独立した日付キーはバックアップ対象になっておらず、日付以前の記録を後から増やすと従量報酬が増える構造だった。

統合後は`medicationRewardPolicy.ts`を正の実装とし、従来の`medicationPolicy.ts`は互換用再exportにした。報酬台帳内の`medicationPolicy`へ実在記録と確定済み旧EXPを一度だけ固定する。旧台帳・残高・服薬記録は削除しない。以後は`medication-day:YYYY-MM-DD`で日次最大10、旧日の追加チェックで旧固定XPを増やさない。新旧イベントの順序と同一バッチを両方保護した。

移行済み情報は既存バックアップversion 1のrewards内で保持。旧修正の`kokoro-medication-reward-policy-v2`を保存した端末も、実在記録と確定済み台帳から新方式へ引き継ぐ。旧キーは削除せず、二重の報酬判定には使用しない。リリース日を11月7日へ固定して遡及適用しない。
